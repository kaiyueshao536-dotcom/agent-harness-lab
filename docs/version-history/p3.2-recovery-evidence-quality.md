## 背景与真实问题

P3.1 修复后，人工依次执行成功诊断、停止 MCP、观察两次失败 Attempt、恢复 MCP 并点击“重试本次诊断”。核心恢复链路工作正常，但验收暴露出新的解释质量问题：

1. 同一诊断任务经历三次执行后，诊断详情显示“工具调用 6”，没有说明这是三条 Trace 的累计；单条 Trace 实际只有两个逻辑工具。
2. 当前任务只要求验证 learning-demo 的 CLS 连通性，成功报告却混入历史案例中的“结算服务 API 延迟升高”。
3. SearchLog 返回 `recordCount=0` 时，报告把“没有匹配日志”扩写为“采集链路存在异常”，超过了证据能够支持的范围。
4. Topic ID 脱敏后的文本出现 `[内部资源标识已隐藏]]`，虽然没有泄密，但占位符格式破损。
5. P2 Gate 仍然 100% 通过，因为原 Dataset 没有声明历史污染或证据谨慎规则。

这些问题都来自真实运行数据，不是为了增加技术名词而虚构的架构需求。

## 实现内容

- 证据链 API 根据同一诊断资源下的 Agent Trace 时间边界派生执行分组，不修改数据库表；旧步骤和工具审计如果无法归属，会进入“未归属历史记录”。
- AIOps 右侧执行链显示“跨 N 次执行累计 M 次工具调用”，每个分组分别展示 Trace ID、状态、耗时、步骤和单次工具数。
- Planner 仍可检索 SOP/历史案例，但 Report 事实上下文不再包含历史正文。
- 工具失败或所有成功 SearchLog 都是零结果时，直接生成确定性 Markdown 回退报告，不调用报告模型。
- 零结果摘要明确说明：当前查询没有匹配到可解析日志，但尚不能区分 Topic 数据、查询条件、时间窗口或采集链路状态。
- 新增 `evidence_cautious` 纯评分规则；P3.2 Dataset 使用 `excludes_all` 明确排除已知历史污染词。
- 脱敏后归一化资源占位符边界，避免重复 `]`/`】`。

## 关键设计决策

- **先利用现有 Trace，不做数据库迁移**：当前重试是顺序执行，Trace 起始时间足以为历史记录分组；未来允许并发重试时再增加显式 `trace_id` 外键。
- **证据不足时减少模型自由度**：零结果报告的目标是如实表达不知道什么，不需要模型创造更丰富的叙事。
- **Planner 参考不等于 Report 事实**：历史案例可以帮助选择查询动作，但当前结论必须由当前告警和当前工具结果独立支持。
- **评测规则保持确定性**：不引入成本高、结果不稳定的 LLM Judge；已知污染词由 Dataset 显式声明，谨慎规则只检查可解释的高风险模式。

## 人工验收证据

同一诊断任务 `diagnostic_aaafadb6ce6a4edfab192ab19a474f83` 保留了三次执行：

| 执行 | Trace | 状态 | 总耗时 | 单次工具 | SearchLog Attempt |
| --- | --- | --- | ---: | ---: | ---: |
| 1 | 对应 91,505 ms 的失败 Trace | failed | 91,505 ms | 2 | 2 次失败 |
| 2 | `trace_8f83cb5e62af44f09827a7dc532183cc` | failed | 82,874 ms | 2 | 2 次失败 |
| 3 | `trace_e5354e227dbf4f1b81e8314c2a3c80c9` | succeeded | 80,464 ms | 2 | 第 1 次成功 |

恢复执行包含 15 个 Span、0 个失败 Span；SearchLog 父 Span 为 503 ms，Attempt 为 476 ms。父 Span 包含子 Attempt，二者不能相加作为总工具耗时。

绑定恢复 Trace 后的学习回归 Gate：通过率 100%、平均分 100%、平均耗时 42,571 ms、总工具调用 3。页面显示耗时变化 0，是因为选择的 Baseline 与当前结果相同；相对之前 40,577 ms 的运行实际约增加 4.91%。

## 安全与成本边界

- 报告和 API 公开值继续隐藏 MCP URL、CLS Topic ID 和凭据；Tool Audit 在 owner 权限边界内保留排障凭证。
- 离线评测 fixture 不包含密钥，不访问模型、MCP、CLS 或数据库。
- 零结果直接使用确定性报告，可减少一次报告模型调用，但不会改变真实 SearchLog 查询产生的云端日志检索费用。

## 已知限制

- 时间分组依赖同一诊断顺序执行；并发重试需要显式执行外键。
- `evidence_cautious` 不是通用事实核验器，只检查零结果场景中的一组可解释高风险模式。
- `excludes_all` 只能发现 Dataset 已列出的污染词；未写入规则的新问题仍需人工验收发现。
- 当前后台 Runtime 仍与 FastAPI 同进程，不提供多节点故障接管。

## 复盘结论

这个版本把“工具恢复成功”推进为“每次执行可区分、当前证据不被历史污染、证据不足时不越界、同类问题进入 Gate”。项目价值不在于使用了复杂框架，而在于从真实测试异常出发，定位数据边界、修复、回归并明确仍然未知的部分。
